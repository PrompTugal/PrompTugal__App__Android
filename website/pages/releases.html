The list is read from the repository’s v0.1.N tags when the site is built. The date is the tagged commit’s date. Each tag is a GitHub prerelease with the signed APK. Build numbers and tags only advance when CI succeeds on dev.

How a build gets a number

CI owns the version. versionCode is the workflow’s run number and versionName is 0.1. followed by that number. Nobody sets either by hand; a local build gets 0.0.0-local. Each push to dev that passes the tests and lint is built as a release APK and AAB. When the signing secrets and Firebase settings are present, it is signed with the upload key, sent to the tester group on Firebase App Distribution, and published as a GitHub prerelease. (The first signed build, 0.1.26, was a GitHub release only; Firebase came with 0.1.27.) A short emulator smoke test then installs and launches the release APK.

Not every run reaches a tag: a run that fails or is cancelled by a newer push makes no release, so run numbers have gaps. The full pipeline is described in docs/ci.md and the article.
