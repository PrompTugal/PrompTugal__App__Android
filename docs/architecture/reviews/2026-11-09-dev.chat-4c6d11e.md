## What is good
- Logic in a controller with the screen's scope; file I/O on `Dispatchers.IO`.
- History is atomic JSON with `org.json` (no new dependency) under `noBackupFilesDir/feature_chat`, with a clear-history button, as Dinis decided.
- Model output is plain text; the only thing taken from it is riskmandate.ai links that pass `Links.isAllowed`, opened on a tap.
- Holds stand mode's idle reset while generating (`HoldIdleWhile`); content only inside `FeatureFrame`; tests with fakes.

## Findings for dev.chat
- **A-chat-1 (medium, before H is enabled):** the model is injected through `LocalChatLlm`, a chat-owned CompositionLocal the host would have to provide, which means the host importing a feature package (README: the host imports no feature package but `StandHost`). Take the model from `context.llm` (FeatureContext, once dev.llm's `LlmService` lands) and keep a small adapter inside chat (`ChatLlm` over `llm.stream(...)`, filtered to tokens).
- **A-chat-2 (low):** the `ChatStore` doc comment says `filesDir`; the code uses `noBackupFilesDir`. Fix the comment.
- **A-chat-3 (low):** `wipeNow()` does file I/O on the main thread in `onDispose`. It is tiny, but launch it on an application-scoped IO path or accept and document it. Confirm the intent of `ChatPolicy.WIPE_ON_LEAVE` in stand mode with stand and the conductor.
- **A-chat-4 (info):** a rotation cancels an answer in progress (the screen scope ends). Acceptable; say so in docs/qa.
