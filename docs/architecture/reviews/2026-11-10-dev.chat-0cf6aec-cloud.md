# Architecture review: dev.chat 0cf6aec, chat's cloud use (spec items 2 to 7)

Verdict: PASS (architecture), with one condition on the store and privacy texts

Reviewer: architect.android@promptugal.ai.dinis, 10 Nov 2026. Scope: `features/chat/` (ChatFeature, ChatController, ChatScreen, ChatModel, ChatStore, LlmServiceChat), `cloud/CloudLlmService` (one line), `feature_chat.xml` (en, pt-PT), tests. Spec: `briefs/2026-11-09__on-device-llm/status/dev.chat.md`, items 2 to 7. Rules: README "Cloud model via OpenRouter". Security reviews the same items separately.

## Against the ruling
- **Opt-in and separation:** `usesCloud = CLOUD_REVIEWED` (false today). Chat takes the cloud only from `context.cloudLlm`, and only if its `location` is CLOUD (a non-cloud service handed in as cloud is ignored), never through `llm`. The host still decides: a key stored, the staff switch on, stand mode off. In stand mode a visitor only ever reaches the on-device model.
- **Item 2, which model:** when both exist, a two-way choice, default Cloud, **never saved**. Rotation or restart returns to the default; the host's switch decides whether the cloud exists at all. One chip always says which ("Cloud: openrouter.ai" with the model id, or "Runs on this device"), never both and never neither.
- **Item 3, labels:** every answer is saved with its source (`cloud:<model>` / `device:<model>`, with older messages counted as device). There is no unlabelled mix on one screen. This is the badge rule as written.
- **Item 4, what is sent:** `buildRequest` gives the cloud the current message plus the system block only, unless "Send earlier messages" is on (off by default, not saved, reset on a new chat and on switching source). `previewSend` uses the same builder, so "Show what will be sent" cannot differ from the request. Nothing from other features, the device or the managed configuration is added. On the device the whole chat is used as before.
- **Item 5, grounding:** shared base prompt v2 from `llm/prompts`. The cloud route adds the two bundled riskmandate.ai texts (the pages' own sentences), and presets keep their own text. Claims stay within riskmandate.ai.
- **Item 6, history:** unchanged: `noBackupFilesDir/feature_chat`, never backed up, with a clear button. Cloud answers are saved with their labels and cost.
- **Item 7, cost, cap and errors:** cost from `LlmStats.costUsd`, fixed messages with no server text, `CAP_REACHED` with a one-tap "Answer on this device". The cloud stays off in stand mode whatever any saved state says (host).
- **Unchanged:** plain-text output, links only through `Links.isAllowed`, no logging of content, no new permission, no new dependency. Tests cover each item (149 chat and cloud tests). The JVM-versus-Robolectric note in dev.chat's status is a sound rule.

## Condition (play and security, before the flip ships beyond the team's tablets)
- `docs/play/privacy-policy.md` and `docs/play/data-safety.md` still describe the cloud as a **DRAFT** with "no code yet" or "not built", and do not name chat. Before `CLOUD_REVIEWED` reaches a build for anyone outside the team, they must describe the merged behaviour and name chat as a cloud screen: only the typed message and the RiskMandate texts by default, earlier messages only by a visible per-request choice, "show what will be sent", labels, caps, never in stand mode. The in-app texts are already true: `cloud_intro`, chat's kicker, summary, history note and cloud note, and mandate's cloud reasons. The app is not on Google Play, so for the team's Firebase tablets the in-app texts are what count.
