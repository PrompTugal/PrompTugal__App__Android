## The contract against the README sketch
- Same shape: `state: StateFlow<LlmState>`, a cold `stream(LlmRequest): Flow<LlmEvent>` (Token, ToolCallProposed, Done, Error), `generate` collecting it, cancellation by coroutine, main-safe, one request at a time.
- **Accepted differences:**
  - `LlmState.Idle(modelId)` (installed, not in memory) is better than overloading NoModel or Ready.
  - `LlmEvent.Error(reason: LlmError, message)` gives features a typed reason (NO_MODEL, LOAD_FAILED, TOO_LONG, INFERENCE_FAILED) to branch on.
  - System prompts are `LlmRole.SYSTEM` messages, not a `system` field. Fine.
- **Not in it, and fine for now:** `installed` and `LlmRequest.modelId` (my README additions for chat's picker). `LlmHost.preferredModelId` is host-side and set by feature G. **A-llm-12 (low):** if chat keeps a model picker, add `val installed: StateFlow<List<InstalledModel>>` to the interface (with a default in the fake) rather than letting chat see `LlmHost`. Otherwise the picker lives in G only, and chat shows the current model's name from `Ready(modelId)`. Decide with dev.chat; the README is updated either way.

## What is good
- **The model proposes, code decides, in one place:**
  - `ToolSpec` (flat typed parameters, max length, enum values, unique names).
  - `check()` / `checkToolCall()`: unknown tool, unknown, missing, wrongly typed, oversize or disallowed arguments are all rejected, and the reason never echoes argument values.
  - `StrictJson`, a strict, bounded, flat-only parser, because `org.json` is lenient. No new dependency.
  - The runtime is set to `automaticToolCalling = false` with `NotExecuted` tool stubs, so nothing runs inside the runtime.
  - This also gives dev.lab the full validator that A-lab-1 asked for: the Lab should use it rather than keep its own.
- **LlmHost** follows the README:
  - one per process, created with the application context;
  - lazy load, GPU first then CPU;
  - SHA-256 checked before loading through `ModelFiles.verifyOnce` (with a verified marker so it doesn't re-hash every time);
  - a Mutex on a single-threaded dispatcher (`limitedParallelism(1)`);
  - an idle unload after 5 minutes and an unload on `onTrimMemory` (background or critical);
  - a fresh runtime conversation per request, so no history leaks between features;
  - `cancelProcess()` on cancellation, and the engine closed on unload;
  - typed errors, never a crash.
- `FakeLlmService` in main, with the same rules (serialised, ends with Done or Error, never runs a tool). It is used by my contract test and is ready for chat, lab and qa.

## Findings for dev.llm
- **A-llm-3 (still open, blocks merging the branch as is):** the branch still carries host lines in `MainActivity.kt`, `app/build.gradle.kts` and `AndroidManifest.xml`, which conflict with app's shell. app re-does them on `work/app`: the dependency and the flag, `LlmHost.create(applicationContext)` held once (an `Application` subclass or a host holder), `onTrimMemory` forwarded, `FeatureContext(..., llm = host)`, the bench route and the Diagnostics entry. Merge dev.llm's own paths (`llm/`, `features/models/`) without the host files.
- **A-llm-13 (low):** the TOO_LONG pre-check is a character ceiling (6 characters per token × 8192). It only catches what cannot possibly fit; the runtime refuses the rest. Say in the KDoc that a feature must still handle `LlmError.TOO_LONG` from the runtime (it does: the runtime error maps to INFERENCE_FAILED today). Map the runtime's context-overflow error to TOO_LONG if LiteRT-LM reports it distinctly.
- **A-llm-14 (info):** `ExperimentalFlags.enableBenchmark` is a process-global flag toggled around engine and conversation creation. It is safe because every call is under the host's Mutex (and the bench runs only when the host is idle), but keep it that way: never toggle it outside `llm/`.
