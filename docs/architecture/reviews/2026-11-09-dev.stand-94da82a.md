# Architecture review: work/dev.stand at 94da82a (0aa99c8 + PIN removed)

Verdict: HOLD

Reviewer: architect.android@promptugal.ai, 9 Nov 2026. Scope: `features/stand/`, `feature_stand.xml` (en, pt-PT), tests. Gate on a trial merge of dev + architect + app + qa + stand + abpdemo + mandate: stand's own tests pass.

## What is good
- Pure, JVM-tested `IdleTimer` with a monotonic clock. Time is counted only while RESUMED (`repeatOnLifecycle`), cancelled with the composition. No threads or timers.
- `ScreenLock` behind an interface with a fake in tests. `startLockTask`/`stopLockTask` go through StandHost's Activity, the one sanctioned place. No DevicePolicyManager. Unpin only if stand mode was on in this composition. Every call is guarded.
- Touch watching is non-consuming, on `PointerEventPass.Initial` at the root, as the architecture asks.
- Keep-screen-on uses `FLAG_KEEP_SCREEN_ON` with no `WAKE_LOCK` (security D3). The PIN was removed (security D2).

## Findings for dev.stand
- **A-stand-1 (HOLD):** the bottom-end corner box sits on top of **every** screen and `combinedClickable` consumes every tap in it, even with stand mode off. Compose hit-testing stops at the topmost sibling, so whatever a feature draws under that 48dp corner is dead. On the trial merge, the right part of abpdemo's Auto-play button lies under it. Fix: compose the corner only when `atHome` (the idle reset brings staff home anyway). The home-screen switch (P4, with app) replaces it later.
- **A-stand-2 (medium):** touches in other windows (any `AlertDialog` a feature opens, including stand's own settings dialog) do not reach the root `pointerInput`. Someone using a feature's dialog for longer than the idle time is sent home. Also check on a tablet that WebView touches (site, through `AndroidView`) reach the root `Initial` pass. Write both in your status page as device checks for qa.
- **A-stand-3 (medium, cross-feature):** abpdemo's auto-play is meant to loop untouched at the stand, but the idle reset sends it home after N minutes. Owners agree the behaviour (see the conductor's routing). Options: (a) idle reset only when no feature asks to stay; that needs a `FeatureContext` signal, and the architect will propose it if wanted; (b) accept going home, and start the loop from home. Do not add a back channel yourself.
- **A-stand-4 (low):** unpin is guarded by `wasOn`, not by "we called `startLockTask`". If the device was already in lock task when stand was turned on (MDM pinned), turning stand off calls `stopLockTask` on a lock the app did not start. Track `weLocked = lock()` instead.
- **A-stand-5 (low):** naming. Prefs file `stand_mode` should be `feature_stand` (docs/architecture/README.md, State). Strings `stand_*` are accepted (rule relaxed to the `<id>_` prefix). `stand_ok` and `stand_cancel` are unused since the PIN went: delete them.
- **A-stand-6 (info):** `keepScreenOn` sets the window flag but is never cleared on dispose. Harmless while StandHost wraps the whole Activity; `LocalView.keepScreenOn` would clear itself.
