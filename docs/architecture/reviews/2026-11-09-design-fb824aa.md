## What is good
- Theme tokens (`Pt.colors`, `Pt` text styles, `Space`, `UiTokens`) are read-only `staticCompositionLocalOf` values and objects of `val`s, with no global mutable state. The serif is `FontFamily.Serif`, the device's own font, so **no font is bundled** and there is no licence to record. Sizes are in sp and follow the user's font scale.
- Components are stateless and take their text from callers: `Page`, `Columns`, cards, badges, and `StateView` (load phases, live region, retry only when given). `Page` is built on `FeatureContent`, so it stays content only, inside the host's frame.
- No new dependency (`app/build.gradle.kts` unchanged). Screenshot and component tests added.

## Findings for design
- **A-des-4 (medium, one title per screen):** `ScreenHeader(kicker, title, summary)` is documented as "the first item of a Page inside FeatureFrame". But `FeatureFrame` already shows the feature's title, so every feature would show its title twice. With P7 (architect c9233a0), `kicker`, `title` and `summary` are on `Feature`, and the host can draw the header itself. Rule:
  - The host's frame (app, shell step 2) draws `ScreenHeader` from `Feature.kicker/title/summary` as the top of the feature's page.
  - Features do not draw their own main `ScreenHeader`; they use it only for sub-screen headings (an article in releases, a scenario in the Lab).

  Change the doc comment to say so. app and design agree whether the frame's header scrolls with the page or stays fixed.
- **A-des-5 (low):** the A-des-2 breakpoints are still split: `LocalWideLayout` at 840dp, the shell's sidebar at 720dp. A 720 to 840dp window gets a sidebar and one-column content, which is fine, but write it down in docs/design so nobody "fixes" one of them.
