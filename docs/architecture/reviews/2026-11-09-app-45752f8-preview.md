## Against the ruling
- **Separate host path:** `Routes.preview(id)` = `preview_<id>`, produced only by Diagnostics > Preview. The underscore cannot collide with a feature id (ids are `[a-z]+`, tested). Accepted in place of my `preview/<id>`.
- `resolveRoute` sends a preview route Home in stand mode, and when the feature is not currently switched off (switched on since, or gone). A plain disabled id still goes Home.
- `resolveOpenFeature(id, standOn, enabledIds, previewIds)`: refused in stand mode; enabled ids are allowed; a disabled id opens as `preview_<id>` only when the host passes `previewIds`, which it does only while a Preview screen is showing. Enabled features never reach disabled ones. As ruled.
- Same `FeatureContext` (`llm` from the process-wide `LlmProcess`, the sanctioned holder) inside the normal `FeatureFrame`, with the kicker "Preview". The label is visible, and features cannot tell.
