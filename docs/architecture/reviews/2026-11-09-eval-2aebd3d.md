## What is good
- **Off the app entirely:** Python standard library only, nothing under `app/`, no Gradle change, no dependency added to the app. The LiteRT-LM Python API is imported late, only by the local backend, from a venv outside the repository.
- **Key handling:** read only from `OPEN_ROUTER_KEY` / `OPENROUTER_API_KEY`, sent only to `openrouter.ai`, never printed, and scrubbed from every record before writing (defence in depth). Error messages carry the provider's response body, never the request.
- **Money:** `budget.py` clamps any cap to `HARD_CAP_USD = 5.00` in code, reserves per call before the request, records OpenRouter's `usage.cost` (or a labelled list-price estimate), is file-locked across processes, and has a per-invocation `--max-cost`. `run --dry-run` prints the worst case first.
- **Data outside the repository:** scenarios and graph come from `--vault` / `$EVAL_VAULT` (default `~/eval-vault`) and results go to `--results` / `$EVAL_RESULTS` (default `~/eval-results`). `eval/.gitignore` also drops `results/` and `*.jsonl` in case someone points inside the repo. This matches Dinis's decision.
- **Honest labelling:** model `closest_to`, `quantisation: provider-chosen, unknown` for hosted runs, the runtime version, thread count and weights SHA-256 for local runs, and `(heuristic)` on scenario 5.
- **Clean shape:** the oracle (what counts as a failure) is separate from the ABP checks (what the policy stops). The tool protocol is one text protocol for all backends. Four versioned formats are documented in `FORMATS.md`, including the replay preset dev.lab bundles and the tablet's loop-mode export.

## Findings for eval
- **A-eval-1 (medium):** the $5 total lives in `<results>/budget.json`. A run with a different `--results` (or a fresh `$EVAL_RESULTS`) starts again at $0, so the "$5 in total" cap can be passed without anyone noticing. Keep the ledger at one fixed path independent of `--results` (for example `$EVAL_BUDGET` defaulting to `~/.config/riskmandate-eval/budget.json`, or the vault), and refuse to start if it cannot be read (rather than treating an unreadable file as $0 spent, which `_read()` does today).
- **A-eval-2 (medium, shared with dev.lab):** there are now two implementations of the same ABP checks: `eval/abpeval/abp.py` (rules `tool_allowlist`, `read_only`, `egress_recipients`, `secret_egress`, `citations_required`, `state_consistency`; actions `block`/`hold`/`flag`) and Kotlin `features/lab/AbpChecks.kt` (a `Block` enum, no `hold`). The tablet's export is re-scored here with the Python oracle, so the two will drift silently. Owner of the format (eval): publish a small set of **golden check vectors** (scenario policy + proposed call or claim → expected verdict) as one JSON file in the format, run by both `test_harness.py` and dev.lab's `AbpChecksTest`. Align the rule names and add `hold` to Kotlin, or drop it from the format.
- **A-eval-3 (low):** a single call can overrun the cap by its cost minus the $0.003 reserve (the check is on the reserve, the record is the real cost). Harmless at these prices; either raise the reserve per model from `models.json` prices × `max_tokens`, or say so in the README.
- **A-eval-4 (low):** `eval/` has no CI job yet, so the 19 tests run only by hand. When release adds the optional job (brief), run the tests there without a key (they need none).
- **A-eval-5 (info):** the default `X-Title` header names RiskMandate. Fine (the brief allows it), but no user or device identifiers should ever be added to requests.
