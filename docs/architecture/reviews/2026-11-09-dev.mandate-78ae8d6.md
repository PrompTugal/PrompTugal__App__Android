## Findings for dev.mandate
- **A-man-1 (HOLD):** the screen draws its own Back button, title and `safeDrawingPadding` inside the host's `FeatureFrame` (on dev since 2bbc37b): two Back buttons, two titles, insets applied twice. Remove them; features draw content only.
- **A-man-2 (HOLD, gate red on the trial merge):** `HostProbe.SAMPLES` fails qa's `everyUrlLiteralInFeatureSourcesIsAllowed`. Architect decision (qa review A-qa-1): end each refused sample's line with `// qa: probe, never navigated`, and never pass `SAMPLES` to anything but `Links.isAllowed`. Merge after qa's exemption lands, or together with it.
- **A-man-3 (medium, once architect e3eb80c is on dev):** use `context.config` and `context.device`, not `ManagedConfig.read`/`DeviceStatus.detect`. The host keeps them current (also on a restrictions change while the screen is open). Key the report's `remember` on them.
- **A-man-4 (medium, cross-feature honesty):** the reach counts files in `files/`, `databases/` and `shared_prefs/`. Once stand merges, `shared_prefs/feature_stand.xml` (or `stand_mode.xml`) shows up as gap: one file nobody mandated. Once site merges, WebView keeps cookies and caches under `app_webview/` and `cache/`, which are not counted at all. Add a mandate entry for stand's settings (a reason "stand settings, on this device only"), and count `app_webview` as storage with its own reason when site lands. The view must stay true as the other features land.
- **A-man-5 (low):** `Mandate.HOSTS` copies the private `Links.ALLOWED_HOSTS`. The probes catch drift at run time, but ask app (For app) to make `Links.ALLOWED_HOSTS` public, and use it.
- **A-man-6 (low):** `getPackageInfo` with every component flag and a walk of three directories runs on the main thread during composition. Small today; move it to `LaunchedEffect` + `Dispatchers.IO` with a loading line if it grows (site's WebView cache can be thousands of files).
- **A-man-7 (low):** `"start_url"`/`"device_label"` literals in `MandateSection`: use `ManagedConfig.KEY_*`.
