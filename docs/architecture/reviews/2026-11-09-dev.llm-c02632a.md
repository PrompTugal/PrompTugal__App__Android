## The five points the conductor asked for

1. **Dependency.** `com.google.ai.edge.litertlm:litertlm-android:0.18.1`. It resolves from Google's Maven repository: the POM is served by `dl.google.com/dl/android/maven2/` (HTTP 200) and is not on Maven Central (404); the project's repositories are `google()` then `mavenCentral()`. Licence: Apache License 2.0 (declared in its POM). Approved, within the in-principle approval in the README. Conditions:
   - **A-llm-1 (medium, before merge):** neither `docs/security/licences.md` nor the in-app list `res/raw/licences.txt` names it yet. security reruns `scripts/licences.sh` and `scripts/osv-check.sh`, and app reruns `app/tools/make-licences.sh`, in the same merge. Otherwise the in-app licence screen is wrong, and the CI licence gate may fail.
   - The `-keep class com.google.ai.edge.litertlm.** { *; }` rule is needed: it is called from JNI and uses reflection, and it ships no consumer rules. Accepted.
   - `<uses-native-library android:name="libOpenCL.so" android:required="false" />` is needed for the GPU backend on API 31+. It is not a permission and not exported. Accepted.

2. **`-Xskip-metadata-version-check`.** The risk is real. It applies to the whole `app` module and silences the compiler's check that a library's Kotlin metadata is a version this compiler understands. Here LiteRT-LM is built with Kotlin 2.4 and the project compiles with 2.0.21. Most of the time it works, as Edge Gallery shows. When it does not, the failure moves from compile time to run time: a wrong inline expansion, a missing intrinsic, a `NoSuchMethodError` on the tablet. It would also hide the same signal for any future dependency. **Recommendation: accept it for the summit, with a tracked follow-up (A-llm-2, for release and app) to bump Kotlin, the Compose compiler plugin and AGP to versions that read 2.4 metadata, and then remove the flag.** Until then, these hold:
   - every call into LiteRT-LM stays in `LiteRtBench.kt` (later the `LlmService` implementation) and nowhere else, which is already the case;
   - qa runs the bench on the tablet, both backends, as part of the device run;
   - no other dependency is added while the flag is on without saying so in the review.

3. **The `modelbench` route.** The host lines (`MainActivity`, `DiagnosticsScreen`, `strings.xml`, `build.gradle.kts`, manifest, proguard) are app.android's files. dev.llm wrote them "for app.android's review", which is acceptable as a proposal, but **A-llm-3 (medium): app.android re-commits or approves them on `work/app`; the conductor does not merge host files from `work/dev.llm`.**
   - **A-llm-4 (medium):** the host now imports `features.models.ModelBenchScreen`. That breaks the rule that the host imports no feature package except `StandHost` (P6, 9 Nov). Move the bench screen into `llm/bench/`. `llm/` is shared infrastructure the host may use, like `LlmHost` later. Keep `Routes.MODEL_BENCH` as a temporary host route until feature G replaces it, then delete the route.
   - **A-llm-5 (medium): visible to visitors.** Diagnostics is reachable by anyone from Home, including at the stand, so anyone can open the bench and start a multi-gigabyte model load. Show the Diagnostics button only when `ModelFiles.find(context)` is non-empty (read off the main thread). Better still, also only in debuggable builds or with stand mode off; but the host cannot read stand settings without importing `features/stand`, so prefer "model present and debuggable build" for the summit build. Its strings are fine.

4. **LiteRtBench lifecycle.** Good.
   - `run()` is a suspend function on `Dispatchers.Default`, so it is main-safe. File scans and the SHA-256 run on `Dispatchers.IO` in the screen.
   - Each run creates an `Engine`, initialises, streams one answer, and closes the conversation (`use`) and the engine in `finally` under `NonCancellable`.
   - Cancellation calls `conversation.cancelProcess()` and rethrows.
   - The run's `Job` comes from the screen's `rememberCoroutineScope`, so leaving the screen or turning the tablet (the Activity is recreated) cancels it and the engine is closed.
   - Only one run at a time (`running`).
   - **A-llm-6 (low):** `ExperimentalFlags.enableBenchmark` is a process-wide flag, toggled around engine creation. Fine while the bench is the only user. The `LlmService` must never touch it, and two benches must not run at once (they cannot today).
   - **A-llm-7 (low):** `ModelBenchScreen` holds a `Job` in `mutableStateOf`. Correct, but when the service exists the bench should go through it (or stay a separate, explicitly debug-only path), so there are never two engines in memory.

5. **APK size.** About 50 MB with arm64-v8a and x86_64 native libraries. Keeping both ABIs is acceptable for now, because CI's emulator smoke test runs on x86_64. **Follow-up A-llm-8 (low, release):** ship the AAB (Play splits by ABI), or add an ABI split or an `abiFilters` arm64-only flavour for the Firebase tablet build, once the smoke test has an arm64 path or is moved to the AAB.

## What else is good
- **Pinned model catalogue:** an exact Hugging Face commit revision (never a branch), file name, size and SHA-256, and the weight licence per model. Gated models are marked `downloadable = false` (adb only; the app never holds a token).
- **Verification:**
  - before any load, check the size, then the SHA-256;
  - a wrong hash deletes the file;
  - a wrong size leaves it (an adb push may still be writing).
  
  All of it is pure, JVM-tested and off the main thread.
- **Storage:** `noBackupFilesDir/models/` for the app's own copies. That is better than my README's `filesDir/models/`: it is excluded from backup by the platform itself, with no rule to forget. The README follows it.
- **Memory:** `MemoryProbe` reads only this process's `/proc/self/status` and the system totals.
- **Tests:** catalogue, verification, report, and the screen with fakes.

## Findings, other
- **A-llm-9 (medium, step 3):** the bench loads a verified file directly from `getExternalFilesDir("models")`. On Android 10 and earlier (minSdk is 26), another app with storage permission could replace that file between the hash check and the load. The weights are public, so this is about integrity, not secrecy. Feature G must copy into `noBackupFilesDir/models/` and verify again before any load, as the status page plans. The service must load only from the internal folder. For the step-1 bench on the Android 14+ tablet, accepted.
- **A-llm-10 (low):** mandate lists `app_webview` and stand's prefs. It must also list `noBackupFilesDir/models/` (and the adb folder while it is used), with a reason, in the merge that makes G visible.
