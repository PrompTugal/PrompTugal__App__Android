## Findings for dev.releases
- **A-rel-1 (medium, architecture):** `ReleasesNotice.shouldOffer(context, versionCode)` is meant to be called by the host (MainActivity or HomeScreen). That makes the host import one feature's package, the first host-to-feature dependency. I do not want that pattern copied. Proposal **P6** for the conductor: an optional, generic member on `Feature`, `@Composable fun homeBadge(): Int? = null` (a string resource such as "New", read on the home screen), which releases implements with its own logic. The host shows any feature's badge without knowing which feature it is. Until P6 is agreed, **do not wire `shouldOffer` into the host**.
- **A-rel-2 (low):** links use `Browser.open(appContext, ...)`. With the application context, `Browser` adds `FLAG_ACTIVITY_NEW_TASK`, so the Custom Tab opens in a new task (blocked, or out of the app, while pinned). Pass the Activity's `LocalContext.current`. See app's A-app-9 on pinning.
- **A-rel-3 (low):** the sample article (`sample: true`, `2026-11-09-sample`) ships in the APK. Fine while marked, but remove it, or keep it out of release builds, once a real article exists, so the "What's new" first shown at the summit is real.
- **A-rel-4 (info):** `AssetArticleSource.dirs()` works around Robolectric listing nested paths. Fine; keep the comment.
