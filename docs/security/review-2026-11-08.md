# Security review of `dev`, 8 November 2026

By dev.android.security@promptugal.ai, for conductor.android. Scope: `app/`, `.github/workflows/android.yml`,
`scripts/make-upload-key.sh`, `devices/amapi.mjs` and `devices/policies/`, `.gitignore`, the Gradle files, and
the git history (12 commits, all branches). The repository is public and Apache 2.0, and the app will be sold,
so every finding is judged as if an attacker has the source.

Read-only for `app/`, `.github/`, `devices/`: the fix is described, the owner applies it. Fixed here:
`.gitignore`, new `scripts/secret-scan.sh`, `scripts/licences.sh`, this folder.

Not checked: GitHub repository settings (branch protection, environments, fork-PR approval, secret scanning,
Actions permissions), because no GitHub access was available; the action SHAs against upstream (see A-6);
behaviour on a real device or against Google's API; the built APK/AAB contents.

## Findings

### A-1 High: URL allow-list bypass (`app/src/main/java/ai/riskmandate/app/Links.kt:7-13`)

`isAllowed` parses the host by string slicing: it cuts at `/`, `?`, `#`, then takes `substringBefore(':')`
**before** `substringAfter('@')`. Kotlin's `substringAfter` returns the whole string when the delimiter is
absent, so cutting at `:` first removes the `@`. I re-implemented the function step for step and checked:

| URL | `isAllowed` | Real destination |
|---|---|---|
| `https://riskmandate.ai:x@evil.example/` | **true** | evil.example (userinfo is `riskmandate.ai:x`) |
| `https://riskmandate.ai:443@evil.example/p` | **true** | evil.example |
| `https://evil.example\@riskmandate.ai/` | **true** | evil.example in browsers (WHATWG treats `\` as `/`); `Uri.parse` and the check disagree |
| `https://riskmandate.ai@evil.example/` | false | covered by the existing test only |

Risk: `start_url` comes from the organisation's EMM (`ManagedConfig.kt:28`), so the app is the trust anchor
that stops a mis-set or tampered managed configuration sending a managed tablet to a phishing page; the check
exists for exactly that and it can be bypassed. Today the only caller is the Open button with `config.startUrl`,
so exploitation needs control of the restriction value, hence High rather than Critical. If any future code
opens a URL from an intent, deep link or page, it becomes remotely exploitable.

Fix (owner applies; replace the body of `isAllowed`, keep the signature):

```kotlin
private val ALLOWED = Regex("""^https://([a-z0-9-]+\.)*riskmandate\.ai(:[0-9]{1,5})?([/?#].*)?$""")

fun isAllowed(url: String): Boolean {
    val u = url.trim()
    // No userinfo, no backslash, no whitespace or control characters anywhere in the string.
    if (u.any { it == '@' || it == '\\' || it.isWhitespace() || it.isISOControl() }) return false
    if (!ALLOWED.matches(u.lowercase())) return false
    // Belt and braces: the platform parser must agree on the host.
    val host = android.net.Uri.parse(u).host?.lowercase() ?: return false
    return host == "riskmandate.ai" || host.endsWith(".riskmandate.ai")
}
```

(`@` anywhere is refused: riskmandate.ai pages need none in the start URL. If the Android `Uri` dependency makes
the pure-JVM tests awkward, drop the last block; Robolectric is already in use.) Add tests:
`https://riskmandate.ai:x@evil.example/`, `https://riskmandate.ai:443@evil.example/`,
`https://evil.example\@riskmandate.ai/`, `https://riskmandate.ai\@evil.example/`, a tab or newline inside the
host, `https://riskmandate.ai.` (trailing dot, refused by the regex, decide if wanted), `HTTPS://RISKMANDATE.AI/`
(allowed), and port forms. Also consider pinning to `riskmandate.ai` and `www.riskmandate.ai` instead of every
subdomain: a dangling DNS record under riskmandate.ai would be trusted by every managed tablet.

### A-2 Medium: release secrets reachable by anyone who can push to `dev` (`android.yml:77-90`, `:100-185`)

The `release` job runs on every push to `dev` with all secrets in scope and no GitHub Environment. Anyone (or
any agent token) with write access to `dev` can edit the workflow in the same push, print the secrets, and use
the Play and Firebase service accounts. The Play step is `status: draft`, which limits blast radius, but the
service-account JSON and the upload keystore are the crown jewels.

Fix: Dinis creates a GitHub Environment `release` with required reviewers (Dinis) and moves the four upload-key
secrets, the Firebase and Play secrets into it; the job adds `environment: release`. Branch protection on `dev`
requiring PRs would also work but conflicts with the team's push-to-dev flow, so the environment gate is the
better fit. Also set Settings, Actions, "Require approval for all outside collaborators" for fork PRs. The
`pull_request` trigger itself is safe today: the `check` job references no secret, `permissions: contents: read`
is set at the top, and GitHub withholds secrets from fork PRs.

### A-3 Medium: enrolment token reusable (`devices/amapi.mjs:174`)

`oneTimeOnly` is only set with `--one-time`; the default token enrols any number of devices for `3600s`.
A photographed or leaked QR code lets anyone enrol a device into the organisation (receiving the policy and the
force-installed app) during that hour. Fix: make `oneTimeOnly: true` the default and add `--reusable` for a
deliberate batch, and print the expiry prominently. Update the README runbook and the tests.

### A-4 Medium: unpinned tool runs with the Firebase credential (`android.yml:143-147`)

`npx --yes firebase-tools@13.29.1` downloads the package and all its transitive dependencies at run time, with
`GOOGLE_APPLICATION_CREDENTIALS` pointing at the service account. The exact version is pinned but the
transitive tree and npm integrity are not. Fix: either use a pinned action for Firebase distribution (pin by
SHA), or commit a small `package-lock.json` for firebase-tools and run `npm ci --ignore-scripts` then
`npx --no-install`, or run it with the service account scoped to the single role `Firebase App Distribution
Admin` (check this is so when Dinis creates it). Lowest effort: least-privilege role plus the A-2 environment.

### A-5 Low: key files on disk (`android.yml:105`, `:143`, `:154`)

`base64 -d > "$RUNNER_TEMP/upload.jks"` and the `printf > fad.json` create the files with the default umask
(644); only `play.json` is `chmod 600`. On a hosted single-tenant runner this is low, but it costs nothing:
add `umask 077` as the first line of each of those three `run:` blocks. The "Remove the keys" step with
`if: always()` is good.

### A-6 Low: pinned actions (`android.yml:37-162`, `docs/ci.md`)

All six third-party actions are pinned by 40-character SHA with the tag in a comment. Good. Two notes:
(1) `actions/cache@5a3ec84e...` (v4.2.3) is pinned but missing from the header comment's list and from the
`docs/ci.md` table; add it. (2) I could not resolve the SHAs against GitHub from this session
(no API access), so "SHA belongs to the stated tag" is unverified; `docs/ci.md` says it was done with
`git ls-remote` on 8 November, which is credible. Ask dependabot (`.github/dependabot.yml`, ecosystem
`github-actions`) to propose updates, since SHA pins otherwise go stale. `r0adkll/upload-google-play` handles
the Play JSON: keep it pinned and review each bump.

### A-7 Low: tokens on the command line (`devices/amapi.mjs:150-157`, `devices/README.md` step 3)

`--enterprise-token <token>` ends up in shell history and `ps`. It is a one-time token that expires, so low.
Fix: accept `AMAPI_ENTERPRISE_TOKEN` from the environment (and prefer it in the README), and warn on `--enterprise-token`.

### A-8 Low: upload key script (`scripts/make-upload-key.sh:12-14`)

`keytool ... -storepass "$P1" -keypass "$P1"` puts the password in the process arguments for the duration
of the command (visible to other local users via `ps`). `upload.jks` and `upload.jks.b64` are created with the
default umask (usually 644). Fix, drop-in:

```bash
umask 077
export KS_PASS="$P1"
keytool -genkeypair -keystore upload.jks -alias upload -keyalg RSA -keysize 4096 -validity 10000 \
  -storepass:env KS_PASS -keypass:env KS_PASS -dname "CN=PrompTugal Android upload key" >/dev/null
unset KS_PASS
```

(`-storepass:env` is supported by JDK 17 keytool.) The script is under `scripts/`, but it already exists, so it is
left for conductor.android to edit; I did not change it. Also the final message says "the same password" for the key
password: fine for Play upload keys.

### A-9 Low: policy placeholders unvalidated (`devices/amapi.mjs:107`, `:161`)

`--start-url` goes into the policy `managedConfiguration` with no check. The app refuses a bad one at run time,
but the operator gets no early error. Fix: in `substitutePolicy`, require `startUrl` to be https and its host
`riskmandate.ai` or a subdomain (parse with `new URL`, reject `username`/`password`), and cap `deviceLabel` at 64
characters without control characters, mirroring `ManagedConfig`.

### A-10 Low: error text and file overwrite (`devices/amapi.mjs:258-261`, `:278-281`)

(1) A non-JSON error body is kept as `{raw: text.slice(0,500)}` and, on a failed call, printed through
`JSON.stringify(redact(data))`; `redact` works on keys, so a token inside raw text is not removed. Fix: on non-JSON
errors print only the HTTP status. (2) `writeSecretFile` uses `fs.writeFileSync(file, content, {mode: 0o600})`;
`mode` only applies when the file is created, so a file that already exists keeps its old permissions. Fix:
`{mode: 0o600, flag: 'wx'}`. Likewise `mkdirSync({mode: 0o700})` does not tighten an existing `AMAPI_OUT_DIR`:
`chmodSync(d, 0o700)` after creating it. Good as is: secret keys redacted at `:199-214`, token never printed, files
0600, credentials only from `GOOGLE_APPLICATION_CREDENTIALS`, `devices/out/` gitignored, `--dry-run` reads no
credentials, ids validated by regex before they enter URLs.

### A-11 Low: policy hardening (`devices/policies/riskmandate-fully-managed.json`)

The policy sets the right core controls (`DISALLOW_INSTALL` for untrusted apps, developer settings disabled,
Play Protect enforced, `playStoreMode: WHITELIST`, add user and modify accounts disabled, windowed OS update).
Nothing in it weakens the device. Settings a hardened tablet would normally add; each is Dinis's decision
because it trades manageability against exposure:
- `safeBootDisabled: true` (safe mode is a way past the managed apps on a stolen device);
- `factoryResetDisabled: true` or leave off deliberately (a reset by a thief clears the enrolment, though Factory Reset
  Protection stays on for managed devices; `factoryResetDisabled` also blocks legitimate recovery);
- `usbFileTransferDisabled: true`, `mountPhysicalMediaDisabled: true`, `debuggingFeaturesAllowed: false` (the last is
  also covered by `developerSettings`);
- a screen-lock requirement (`passwordPolicies` or `requirePasswordUnlock`) unless the tablet is intentionally
  lock-free; with none, whoever holds the tablet sees what the app and Chrome show;
- `tetheringConfigDisabled`, `bluetoothConfigDisabled`, `networkEscapeHatchEnabled: false` as wanted.
Also: Chrome is force-installed and unrestricted, so a user can browse anywhere; the app's allow-list protects
only the app's own button. That is a design choice (Custom Tabs need a browser); a managed Chrome policy
(`com.android.chrome` `managedConfiguration` with `URLAllowlist`/`URLBlocklist`) would enforce it. The
`statusReportingSettings` collect application, hardware, memory, display and power data: acceptable, but say so in
the privacy notice before the app is sold; `networkInfoEnabled: false` is right. The OS update window
(02:00 to 05:00) delays security updates by up to a day: fine.

### A-12 Low: build supply chain (`gradle/wrapper/gradle-wrapper.properties`, repo root)

`distributionUrl` is https and `validateDistributionUrl=true` is set (good), but there is no
`distributionSha256Sum`, so a tampered Gradle download would be accepted. There is no
`gradle/verification-metadata.xml`, so dependency artifacts are not checksum-verified. Repositories are
limited to Google and Maven Central with `FAIL_ON_PROJECT_REPOS` (good), and versions are fixed (BOM, no
dynamic versions). Fix: add `distributionSha256Sum` from gradle.org for 8.11.1; run
`./gradlew --write-verification-metadata sha256 :app:dependencies` once, review and commit the file (a
verification file needs refreshing on each dependency change). Confirm `gradle/actions/setup-gradle` validates the
wrapper jar in v4.4.4 (I believe it does by default, but did not verify), else add
`gradle/actions/wrapper-validation`.

### A-13 Info: browser hand-off (`app/src/main/java/ai/riskmandate/app/Browser.kt:19-35`)

`CustomTabsClient.getPackageName(context, emptyList())` picks the default or any Custom-Tabs browser; the fallback
`ACTION_VIEW` + `CATEGORY_BROWSABLE` lets the system choose any app that handles https URLs. Both only ever get a
URL that passed `isAllowed` (so A-1 matters), and the app sends no data and no extras, so there is nothing to
steal from the app. Accepted: the user's browser is the user's choice. On managed tablets Chrome is forced by policy.

### A-14 Info: signed APKs public (`android.yml:130-134`, `:171-180`)

With the upload key present, CI attaches the signed APK to the artifact and to a public prerelease. In a public
repository anyone can download it. That is consistent with open source, and the upload key is not the app-signing
key under Play App Signing, so a downloaded APK cannot update the Play version. It does mean the unsold build is free
and a Firebase-tester build is public. If the paid app must not be freely downloadable from GitHub, drop the
`gh release create` step and keep the artifact private (set artifact visibility by not uploading signed builds
from the public repo). Dinis decides; it is a business question, not a vulnerability.

### A-15 Info: committer addresses

Commits are authored as `<role>@promptugal.ai` mailboxes, which are agent identities, not personal addresses.
`CLAUDE.md` says no contact details in the repository; confirm these role addresses are acceptable to publish (the
CLAUDE.md of this repo itself names them). Nothing else personal is in the tree.

### L-1 Low: licences screen

Apache 2.0 section 4(a) requires giving recipients a copy of the licence. The app has no "Open source licences"
screen. Add one (a static screen with the contents of `docs/security/NOTICE.draft` once adopted, plus the licence
text), or link it in the Play listing. Licence result: 84 runtime artifacts, all Apache-2.0
(`docs/security/licences.md`), none flagged.

## Reviewed and sound

- Manifest (`AndroidManifest.xml`): the only component is `MainActivity`, exported as a launcher (MAIN/LAUNCHER, no
  other filters, no data or deep-link filters); it reads no intent extras. `allowBackup="false"`,
  `dataExtractionRules` exclude the root domain from cloud backup and device transfer, `usesCleartextTraffic="false"`
  and a network security config with cleartext off and the default system trust anchors (no user CAs, no pinning,
  no debug overrides). No permission beyond INTERNET; `<queries>` is package visibility only. The restrictions
  receiver is registered `RECEIVER_NOT_EXPORTED` (`MainActivity.kt:50-55`) and unregistered in `onPause`.
- `ManagedConfig.kt`: types checked (`as? String`), label stripped of control characters and capped at 64, a
  refused URL falls back to `Links.HOME` and is flagged; it never throws. Its safety depends on A-1.
- R8: `isMinifyEnabled` and `isShrinkResources` true for release; mapping file not published by CI (fine; keep it
  that way or upload it only to Play for deobfuscation). `proguard-rules.pro` has no keep-all rules.
- Signing: keystore path and passwords only from environment variables; nothing signs a debug build with the upload
  key; `*.jks`, `*.keystore`, `google-services.json`, `*service-account*.json` ignored, and now more spellings.
- Workflow: top-level `permissions: contents: read`, `contents: write` only on the release job; concurrency group;
  `timeout-minutes`; no `pull_request_target`; no `${{ ... }}` of untrusted input (branch names, titles) in `run:`
  (only `github.run_number`, which is numeric); `workflow_dispatch` input `play_track` is a choice, and reaches the
  shell through `env`; the release job is gated to `refs/heads/dev`. The release note uses `git log -1 --pretty=%s`
  inside double quotes: an attacker-controlled commit subject is data, not code, in that position.
