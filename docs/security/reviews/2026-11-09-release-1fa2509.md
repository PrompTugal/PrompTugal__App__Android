## Checks

| Check | Result |
|---|---|
| `resolve-commit.sh` | PASS. It accepts only 7 to 40 lower-case hex digits, asks git for the objects whose name starts with them (`rev-parse --disambiguate`, no ref is consulted), keeps the commits and requires exactly one. I ran it by hand: `abc`, uppercase, `zzzzzzzz`, `../x` and `HEAD` are refused for their form; `0000000` names none and is refused; 12 and 40 digits of a real commit resolve to it; with a branch created named like the first 8 digits of an older commit the result is that older commit, not the branch's tip |
| Collisions | Someone who can push could create another commit with the same short prefix (7 hex digits are cheap to brute-force); the script then sees two commits and refuses. That is a denial of the short form, never a redirect: use 12 or more digits |
| `play.yml` | PASS. Both inputs are resolved by the script and the resolved full shas are printed into the run summary before the verifier runs; the push path and the verifier are unchanged |
