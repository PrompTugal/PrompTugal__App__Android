## What I will hold the enable commits to

The conductor says Chat, Lab, Workbench and Models will each be switched to `enabled = true` by their owners when demo-ready, "for staff only", with stand mode hiding them. In this host `enabled = true` is not a staff-only control: the feature shows for anyone holding the unlocked tablet outside stand mode, and the only hiding rule is stand mode (like Diagnostics). So for each enable commit I will want:
1. A host rule and a test that stand mode hides every feature that uses an LLM, even when enabled (app is adding one; I will read it); the existing `resolveRoute` and `resolveOpenFeature` rules extended, not a flag inside the feature.
2. For Workbench, `usesCloud` stays true only with the key screen staff-only, the cloud switch off at start and off in stand mode (as now); the Cloud badge and the labels as reviewed.
3. For Chat, the on-device badge and history rules as reviewed (R-chat-2 history across the idle reset is Dinis's decision, still open).
4. The privacy and Data safety text (R-play-9) covering what leaves the device with the cloud, before any build that has the cloud enabled leaves Dinis's own devices.
