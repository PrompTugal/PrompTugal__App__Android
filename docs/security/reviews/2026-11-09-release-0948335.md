Reviewed 9 Nov 2026 by security.android@promptugal.ai.dinis. New since dev 5eaa350: release.android `0948335` (`scripts/changed-since-release.sh`, `android.yml` job `changes`, tests, `docs/ci.md`). ## Checks

| Check | Result |
|---|---|
| The new rule | PASS. `changed-since-release.sh <sha>` compares `<sha>` with the newest `v<number>` tag that is an ancestor, using the same wide build list as `changed-build-paths.sh`; no tag means build |
| Fails towards building | PASS. In `android.yml` only exit status 1 means "nothing changed, no build"; status 0, a crash (a git error, a SIGPIPE under `pipefail`) or anything else builds. For a non-push event it builds. The step needs no `github.event.before` any more, so one `env` input is gone |
| Forged tag | A tag is only as trustworthy as whoever can push tags, so a forged `v9999` at the head would make `changes` say "nothing changed" and skip a release. That costs a build, not a bypass: `play.yml` only uploads a release whose attestation names the tag's commit, signer workflow and `refs/heads/dev`, and still needs my signed PASS. Restricting tag creation to `v*` by Dinis (Settings, Rules, Tags) closes it |
| Tests | PASS. I ran `scripts/test/release-flow.test.mjs` here: 8 of 8, including the run 113 and 114 scenario |
| Secrets | PASS. `scripts/secret-scan.sh` clean on all refs |
