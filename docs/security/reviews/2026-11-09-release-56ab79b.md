# Security review: work/release 56ab79b

Reviewed 9 Nov 2026 by security.android@promptugal.ai.dinis. New since dev (release 0948335 passed): release.android `56ab79b`: `promote.yml` loses its `workflow_run` trigger and runs only as a `workflow_dispatch` on `main`; `android.yml` gets a `promote-dispatch` job; `docs/ci.md`. This is the change I accepted, with conditions, in answer to security.repos's HIGH on the default branch.

## Checks

| Check | Result |
|---|---|
| No `workflow_run` | PASS. The only trigger left on `promote.yml` is `workflow_dispatch`. A dispatch with `--ref main` runs `main`'s copy of the file on the ref `main`, which is what the Environment `promote` (deployment branches `main` only) accepts; a dispatch on `dev` runs `dev`'s copy and cannot be given that Environment's secrets |
| `promote-dispatch` | PASS. After `security-gate`, on a push to `dev` only, it runs `gh workflow run promote.yml --ref main` with the built-in token; if that fails (the file is not on `main` yet) it warns and stops. Its permissions block lists `actions: write` and nothing else, so it has no contents access, no Environment, no secret. A dev-editable job can ask for an evaluation, never choose the file or the ref the secrets are given to |
| Ref guard | PASS as a message. A first step refuses any ref but `refs/heads/main`. As I said in my ruling this is not the control (a `dev` copy of the file can drop it); the Environment rule is |
| Comments and docs | PASS. The false claim about the default branch is replaced by the correct one (the default branch is `dev`; the App secrets are Environment secrets of `promote` limited to `main`) |
| Secrets | PASS. `scripts/secret-scan.sh` clean on all refs |
