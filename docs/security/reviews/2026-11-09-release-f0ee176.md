| Push paths filter | A push to `dev` runs the workflow only if it touches `app/**`, Gradle files, `gradle.properties`, the wrapper, `.github/**` or `scripts/**`. Everything that goes into the app, the release job or the gates matches. Not covered, by design: `docs/`, `board/`, `briefs/`, root documents, `devices/` (see R-rel-8). Pull requests and `workflow_dispatch` have no filter. Skipping a docs-only push cannot skip a gate for code, because the gate runs on whatever else changed in the push. |
| Concurrency | `check`, `licences` and `smoke` cancel older runs of the same ref; `release` has its own group with `cancel-in-progress: false`, so a running release (which may be distributing) is never cancelled, and a newer waiting release replaces an older waiting one. Pull requests get a group per `refs/pull/N/merge`, so one PR cannot cancel another's checks or a `dev` run. If `check` of an older push is cancelled by a newer one, that older push's `release` is skipped (its `needs` fail), and the newer push carries the same commits. |
