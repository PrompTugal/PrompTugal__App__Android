## Checks

| Check | Result |
|---|---|
| The model proposes, code decides | PASS. The service never runs a tool. Each step's text and native proposals reach `PathRun`: text and proposals together are cut to 16 calls, then `ToolProtocol.check` allows four per turn, then `checkToolCall` (exact tool name, strict flat arguments, required, typed, 2000 characters per string, unexpected arguments refused), then, on the ABP lane, `AbpChecks`, and only then a fake tool |
| Native proposals | PASS. `fromProposal` keeps the model's exact argument text; it is what `checkToolCall` parses, with the strict parser and its 4096-character bound. A proposal that does not parse is shown as empty and refused. Names are cut to 64 characters, so a long name cannot match a shorter tool |
| Size bounds | PASS. Model text cut at 16,000 characters before anything reads it; tool results handed back cut at 2,000; the assistant text replayed to the model is cut at 16,000; the loop ends at the scenario's `max_steps` |
| Visitor's typed instruction | PASS. At most 280 characters, trimmed, shown to the visitor exactly as typed, appended to what the scenario's trap tool returns (or added to the task as a note). Tools, policy and failure rule are unchanged. It goes only to the on-device model and the fake tools; nothing is sent anywhere, written to a file or placed in a link or intent |
| Output | PASS. Everything is shown as plain text; the screen has no link, browser, intent or clipboard use, and `LabImportsTest` and qa's `LlmSandboxTest` still pass |
| Failures | PASS. A service error or any other exception ends the run as "failed" and counts in no counter; cancelling stops the model |
| Stand mode | "Set up a model" uses `openFeature`, which the host refuses in stand mode |
| New permissions, storage, network | None. `scripts/secret-scan.sh` clean |
