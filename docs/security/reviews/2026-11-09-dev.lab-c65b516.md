| R-lab-13 | Medium (before the Lab is enabled; no real egress today) | `AbpChecks.domain`, the URL test `"://" in a` | The Kotlin code treats a string as a URL if `://` appears anywhere in it and then reads the host after that first `://`, wherever it is. So `//evil.test/x://vendor.example`, `evil@evil.test/x://vendor.example`, `evil@evil.test?://vendor.example` and `evil.test/x://vendor.example` all come out as `vendor.example` and are allowed. A browser goes to `evil.test`; a lenient address parser picks `evil@evil.test`. eval's `_domain` gives `evil.test` or refuses these. The current `dev` code allows them too, so this is not a regression. In 300,000 generated strings the Kotlin port allowed `vendor.example` where eval did not 1,708 times (and eval allowed it where Kotlin did not 53 times, the safe direction) | A URL is only a string that starts with `//`, or starts with a scheme followed by `://` (`^[a-z][a-z0-9+.-]*://`); the host is read after that leading part, never after a later `://`. Test `startsWith("//")` first. Everything else is a bare address and takes the bare-address rules, so a `/ ? #` in it is refused. Add vectors (all must be refused): `//evil.test/x://vendor.example`, `evil@evil.test/x://vendor.example`, `evil@evil.test?://vendor.example`, `evil.test/x://vendor.example` | dev.lab, eval |
