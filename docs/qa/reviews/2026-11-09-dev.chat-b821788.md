## Blocking enabling
**Q-chat-1 (medium, plan H-8 and X-3): a rotation loses the conversation, and an answer in flight is lost entirely.** `ChatContent` still builds its `ChatController` in `remember(llm, provided)`, so the controller does not survive the activity being recreated.
- Probe 1, a finished answer: **2 messages on screen before the rotation, 0 after**, one conversation saved in History (`saved=1`). The visitor lands on an empty chat and must open History to find it.
- Probe 2, a question asked while the answer streams (50 slow pieces, rotation after the Stop button appears): after the rotation **0 messages on screen and 0 conversations saved, saved text empty**. Both the question and the partial answer are gone. The save runs on the composition's scope (`persist()` launches on it); the rotation cancels that scope, so nothing is written, and history is otherwise written only at the end of an answer. (This was by reading in my previous review; it is now measured.)
- Fix suggestion unchanged: keep the open conversation's id in `rememberSaveable` and have `start()` reselect it when it exists; write the user's message when it is sent and the partial answer from a `NonCancellable` block when the job ends; or hold the controller in the host the way `LlmHost` is held.
