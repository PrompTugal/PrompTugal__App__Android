## The fix, read
- The screen keeps the open chat's id in `rememberSaveable` (`openId`) and passes it to `ChatController.start(reopen)`; it is reselected when it was saved, else a new empty chat opens. Pass.
- `send()` writes history right after the user's message (before the answer starts), and the end of an answer writes it again inside `withContext(NonCancellable)`, so a rotation or leaving the screen still saves the partial answer. An empty placeholder for an answer that has not started is not saved. Pass.
- A race I checked for: the old controller's final write against the new controller's first read (they use separate store instances, so `@Synchronized` is per instance). The file is written to a temp name and renamed, so a reader sees either the old or the new complete file; across 8 runs of the in-flight probe the new screen always saw the question. I cannot rule out a very slow write losing that race on a loaded tablet; the cost would be one answer missing from History, never a corrupt file.
