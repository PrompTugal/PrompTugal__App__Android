## Blocking
- **Q-site-1 (blocker): does not build on `dev`.** The architect's FeatureContext v2 (on `dev`) removed `FeatureContext.activity`; `SiteFeature` still calls `Browser.isOffline(context.activity)`. Fix: merge `dev` into the branch and read the context in the composable (`val ctx = LocalContext.current`, then `remember { OfflineSwitch(Browser.isOffline(ctx)) }`; a composable call cannot sit inside the `remember` lambda), or use `context.device`/`config` if enough.

## Findings (fix with the blocker, then I re-review)
- **Q-site-2 (medium, verified): two Back buttons.** Opened through `MainActivity`, the host's `FeatureFrame` draws Back and the title, and `SiteScreen` draws its own Back, title and tabs row: probe `PROBE back buttons: frame=1 site=1` (`2026-11-09-dev.site-e6c92f0.probe.kt.txt`). The architecture rule is that a feature draws only its content. Keep the tab row; drop `SiteTags.BACK`, the title and one `safeDrawingPadding` (the frame already applies it; two of them eat vertical space in landscape). All three feature screens do this; see the cross-cutting note in the dev.mandate review.
- **Q-site-3 (medium, verified, plan A-10): rotation resets the tab.** `tabIndex` and `loadKey` are `remember`, not `rememberSaveable`, and the `OfflineSwitch` is re-created from connectivity. Probe: select "How it works", recreate the activity, the tab is no longer selected (`selected after rotate: false`) and the WebView reloads the home page. On a tablet at a stand, someone turning it loses their place. Save the tab index (and the offline flag) with `rememberSaveable`.
- **Q-site-4 (low):** `BackHandler` is registered in the screen, the host registers one too; Compose uses the innermost, so WebView history wins: correct, but nothing tests it. The visible frame Back skips history by design.
- **Q-site-5 (info):** a server-side redirect of a sub-resource to another host is not seen by `shouldInterceptRequest` on every WebView version (known platform limit); main-frame redirects do go through `shouldOverrideUrlLoading`. The page is riskmandate.ai's own; residual risk low.

- Offline copy: six bundled pages from `res/raw`, snapshot date shown, banner with "try online", falls back on a main-frame error (A-4, A-5). Pages are riskmandate.ai's own markup; the plan's claim check (X-9) holds because the text is the site's.
- pt-PT: all site strings translated (`FeatureStringsTest` passes).
- Tests: `SitePolicyTest`, `OfflineSwitchTest`, `OfflineCopyTest`, `SiteScreenTest`: URL decision, mode switching, page lookup. Gap: nothing drives `SiteWebViewClient` (needs a WebView; Robolectric's is a shadow), so A-6 to A-9 are manual on a tablet.

## Guard changes made while reviewing
Three of my guards fired on this branch and were false positives of mine, not the code: the bare `"https://"` prefix, `allowFileAccess = false` (a `false` value), and a gate check that looked per file instead of per feature (`SitePolicy` is the gate). I made the guards precise (scheme-only literals skipped; only `= true` settings flagged; per feature, navigating files must name `Links.` or a type from a file that does) and mutation-checked them again.
