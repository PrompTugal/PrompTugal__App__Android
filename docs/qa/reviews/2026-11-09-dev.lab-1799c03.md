## Blocking enabling
**Q-loop-1 (medium, plan I-4 "counters survive rotation", X-3): a rotation ends the loop and wipes its counters.** `LabScreen` holds the loop in `remember(scenario.id) { LoopState() }` and runs it on `rememberCoroutineScope()`; neither survives the activity being recreated. Probes: (1) a *finished* loop (5 runs): the counters and the "1 in X" headline are on screen before the rotation (counters 1, headline 1) and **gone after (0, 0)**, with the Loop mode still selected; (2) a loop *in progress*: after the rotation **no counters tile, the Run button is back** (the loop was cancelled). A 20-run loop takes minutes on the tablet; the tablet auto-rotates if someone turns it, and the results of the run are lost. Fix suggestion: keep the finished counters (small: a list of `RunScore`) in a `Saver`, so a rotation after the loop keeps what was measured; and either hold a running loop in the host (like `LlmHost`) or accept that a rotation stops it but keep the counters so far and say "Stopped: the screen was turned". Until then the device guide tells Dinis not to rotate during a loop.
