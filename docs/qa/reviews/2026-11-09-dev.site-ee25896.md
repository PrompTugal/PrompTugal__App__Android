## New in this head, read and checked
- **Offline copy on an app-owned origin** (`https://appassets.androidplatform.net/assets/feature_site/`): `SiteAssets.serve` answers every request with that prefix from `assets/feature_site/` and never returns null for it, so nothing on that origin goes to the network; the path must match `^[A-Za-z0-9][A-Za-z0-9._/-]*$` with no empty, `.` or `..` segment, so no `%2e%2e` and no traversal; `isAssetUrl` rejects `@`, backslash, whitespace and control characters and matches case-sensitively on the full prefix, so `appassets.androidplatform.net.evil` and other paths on that host are not the origin (they are EXTERNAL and, as sub-resources, blocked). It replaces `res/raw` pages and `file://` is never used. `FeatureLinksTest` exempts only this literal (and its `$ASSET_HOST` template form) in the `site` package, and pins `ASSET_HOST` to that host.
- **External links:** a link outside the allow-list is handed on only for a **real tap on the main frame** (`hasGesture() && !isRedirect`); scripts, redirects and frames never open anything (security R-ext-1). The system browser gets it through `Browser.openExternal`: https only (`Links.isExternalOk`), no userinfo, not while the screen is pinned (stand mode). My new `externalGateRefusesWhatIsNotPlainHttps` (23 refusals, 3 accepts) passes and `featuresNeverLaunchIntentsDirectly` shows no feature fires an intent itself.
- **WebView hardening:** all denied (permissions, geolocation, file chooser, new windows), SSL errors cancel, `onRenderProcessGone` handled (the app does not die), site data cleared on open and on close, no downloads, remote debugging untouched. My `aWebViewFeatureLocksTheSettingsDown` passes.
