## Against the plan
- **G-2 pinned hosts and URLs, G-5 redirects: pass.** The first URL is always a pinned `ModelSpec.url` (repo, full commit, file name). Redirects are followed by hand, at most 5, and every hop must be https, port 443, no user info, host `huggingface.co`, `hf.co` or a well-formed `*.hf.co` (regex, so `evilhf.co`, `hf.co.evil.com`, `huggingface.co.evil.com`, `-x.hf.co`, `a..hf.co` are refused; owner's tests cover them). A refused hop is never opened (the policy runs before `open`). `Authorization` and `Cookie` are never sent, caches off, `Accept-Encoding: identity`, connect and read timeouts. The browser and WebView allow-list does not grow (`Links` untouched).
- **G-3 checksum mismatch deletes the file: pass.** SHA-256 over the finished `.part`, then an atomic rename and a marker; a mismatch deletes the part and nothing is installed. Probes: a single flipped bit in a file of exactly the right size, and a corrupt earlier partial that is completed with good bytes, both end in `InstallFailure.HASH`, no final file, no part, no marker.
- **G-4 resume: pass.** `.part` plus `Range`; a 206 whose `Content-Range` is not `bytes <have>-…/<size>` restarts from zero once and then gives up; a server that answers 200 to a resume restarts cleanly; a stale part longer than the pinned size is discarded (probe); a dropped connection keeps the part (owner's test). **Cancel (leaving the screen) keeps the partial file and installs nothing; the next try resumes and installs the right bytes** (probe: 524,288 of 2,000,000 bytes kept after a cancel, then completed).
- **Size enforcement while streaming:** more bytes than the pinned size ends the download (`SizeExceeded`) and deletes the part; a `Content-Length` that disagrees is refused.
- **G-6 storage check: pass.** Room for the rest plus a 500 MB margin is checked before any connection; probe: with no room no connection is opened.
- **G-7 adb fallback: pass.** An adb file is size-checked, copied into `noBackupFilesDir/models/` and verified again after the copy; on success the source is deleted to free space, on a bad file it is kept for inspection (owner's tests).
- **G-9 storage:** `noBackupFilesDir` (never backed up); the adb folder is app-specific external storage. app's backup rules now also exclude the device-protected domains.
- **G-10 no new permission or exported component, no foreground service:** confirmed in the merged release manifest. The download runs in the screen's coroutine; leaving the screen cancels it (and keeps the part), so an app in the background does not keep downloading. That is a product limit to say plainly to Dinis: **a 2.6 to 3.7 GB download must be watched with the screen open** (the device guide says so).
- **G-11 privacy line: pass.** `models_privacy` = "Downloads a model file once from %1$s. Nothing you type leaves the device." in English and pt-PT, with the host filled in; `docs/play/privacy-policy.md` and `data-safety.md` carry the matching DRAFT text for the build that enables G.
- **G-8 delete:** `delete` removes the file, the marker and any part (owner's test).

## Findings
- **Q-g-1 (low, claim accuracy):** the screen names one host, `huggingface.co`, but the bytes arrive from Hugging Face's CDN (`us.aws.cdn.hf.co` and similar, same operator, allowed by the policy). The line is true of the first connection and not of the data connection. Suggest "from huggingface.co (and its download servers, hf.co)", in both languages and in the privacy draft. Not blocking.
- **Q-g-2 (info):** the verified marker is keyed to size, modification time and hash; a file replaced with the same size and a restored mtime would be trusted until it is next hashed. Only this app and adb can write the folder, so I accept it, as for the bench.
- **Q-g-3 (info, product):** no download in the background (see G-10).
- Not tested here (needs the tablet): G-1 the screen on a real device, G-12 airplane mode after setup, the real redirect chain (host names the live download passes through). The device guide Part 2 covers them when Dinis runs it.
