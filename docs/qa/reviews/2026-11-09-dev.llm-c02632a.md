## Blocking
**Q-llm-1 (medium; blocks because the bench is Dinis's first contact with the runtime on a minified build): a runtime that cannot start crashes the app instead of reporting.** `LiteRtBench.run` constructs `Engine(...)` *before* its `try`, and its `catch` handles `Exception` only. An `Error` (`UnsatisfiedLinkError` when the native library does not load, `NoClassDefFoundError` or `NoSuchMethodError` from R8 or from the `-Xskip-metadata-version-check` flag, `ExceptionInInitializerError`) is not an `Exception`, so it escapes the coroutine in `ModelBenchScreen` (`scope.launch`, no handler) and takes the process down. Probe `aRuntimeThatCannotStartIsReportedNotThrown`: `LiteRtBench.run` throws `java.lang.UnsatisfiedLinkError: Failed to load native library litertlm_jni` (that is what a JVM does; a tablet with a missing ABI or a stripped class would do the same). On the tablet the first run is on a **release** APK that the JVM tests never see (R8, native lib, metadata flag); if anything there is wrong, the best outcome is a readable "The run failed: NoClassDefFoundError ..." in the report Dinis copies, not a closed app and no numbers.
Fix: move `Engine(...)` inside the `try` (declare `var engine: Engine? = null`, close with `engine?.close()`), and catch `Throwable` after the `CancellationException` branch (`catch (e: Throwable)`, keep the 300-character message, name the class). `OutOfMemoryError` and the kernel's low-memory kill cannot be caught; the report text and the guide tell Dinis what a silent close means.
