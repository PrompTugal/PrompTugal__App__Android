## Step 2: the LLM contract (for dev.chat, dev.lab, qa, architect)
All in `app/src/main/java/ai/riskmandate/app/llm/`:
- `LlmService.kt`: `interface LlmService { val state: StateFlow<LlmState>; fun stream(LlmRequest): Flow<LlmEvent>; suspend fun generate(LlmRequest): LlmResult }`. States `NoModel`, `Idle(modelId)` (installed, not in memory), `Loading`, `Ready(modelId, backend)`, `Failed`. Events `Token(text)`, `ToolCallProposed(name, argsJson)`, `Done(LlmStats)`, `Error(LlmError, message)`; every stream ends with exactly one Done or Error. `LlmRequest(messages, tools, settings = Sampling.DEFAULT, maxTokens = 512)`; messages `LlmMessage.system/user/assistant/toolResult`. Stateless: send the whole conversation each time. Cancel = stop collecting. Main-safe, one request at a time.
- `ToolSpec.kt`: a tool declared in Kotlin (`ToolSpec(name, description, params)`, flat `ToolParam`s: string with max length and optional allowed values, integer, number, boolean). `checkToolCall(tools, proposal)` matches the name exactly against the feature's own list and checks arguments with `StrictJson` (flat object only; repeated keys, single quotes, unquoted words, nesting, trailing commas, text after the object, over 4096 characters: all rejected). Result `ToolCheck.Accepted(tool, typedArgs)` or `ToolCheck.Rejected(tool, reason)`; reasons never echo values. The service never runs a tool.
- `FakeLlmService.kt` (in main, for previews and tests): scripted replies (`FakeReply(text, toolCalls, error)`), optional per-token delay (to test Stop), records requests, same one-at-a-time and cancellation rules.
- `LlmHost.kt`: the real service, one per process. `LlmHost.create(context)` (app holds it, e.g. in an `Application` subclass or a host holder, and passes it as `FeatureContext.llm`). Serves only models in the internal folder (`noBackupFilesDir/models/`, where G installs; the adb folder is the bench's only), from the downloadable catalogue (E2B and E4B), the preferred one (`preferredModelId`, G's choice) or else the first. Before a first load it checks size and SHA-256, skipping the hash when a verified marker (`.<file>.verified`: size, modification time and pinned hash) still matches (security G.3); a failed check deletes the file and sets `Failed`. Loads lazily on the first request, GPU first then CPU; one request at a time on its own single-threaded dispatcher; unloads after 5 idle minutes and on `onTrimMemory(TRIM_MEMORY_BACKGROUND or RUNNING_CRITICAL)`; `refresh()` after G installs or deletes; `unload()`. Engine context 8192 tokens (brief: 4K to 8K); requests that cannot fit are refused with `TOO_LONG` up front.
- `LiteRtRuntime.kt` (behind the `LlmRuntime` seam, the only service file touching LiteRT-LM): a fresh runtime conversation per request (system messages become the system instruction, earlier turns the initial messages), tools described through `OpenApiTool` with automatic tool calling off, so proposals come back as `ToolCallProposed` and nothing runs; Stop cancels the native call (`cancelProcess`); stats from the runtime's benchmark counters.
- Tests: `ToolSpecTest`, `FakeLlmServiceTest`, `LlmHostTest` (fake runtime: lazy load, GPU to CPU fallback, load failure as state, tampered file deleted and never loaded, marker invalidated by a change, preferred model and switching, idle and memory-pressure unload, cancellation frees the lock, too long).
